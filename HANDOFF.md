# TravelBase — исходники для передачи

Снимок: 23 сентября 2026.
Это рабочая версия веб-приложения и заготовки Telegram Mini App. Боевые сервер, модель и база **не подключены**: без `DATABASE_URL` приложение само поднимает встроенный Postgres (PGLite).

## Как запустить

Нужен Node.js 22.

```bash
npm install
npm run dev
```

Открыть http://localhost:8080

Проверки:

```bash
npm run typecheck
npm run build
```

`npm run dev` обязательно через npm-скрипт: он подмешивает `.grok/app-env.json`. Не запускать `vite` напрямую.

## Стек

- React 19 + TanStack Start / Vite + Tailwind 4
- REST: `src/routes/api/$.ts` → `src/lib/travelbase/handlers.ts`
- БД: Postgres. `DATABASE_URL` задан → Neon/любой Postgres (`pg`). Не задан → PGLite (WASM). Миграции в `migrations/`.
- Авторизация браузера: Better Auth (email/пароль). В Telegram Mini App регистрация не показывается: клиент шлёт заголовок `X-Telegram-Init-Data`, сервер сверяет HMAC, если задан `TELEGRAM_BOT_TOKEN`, и привязывает профиль к `telegram_id`.
- Карты: Leaflet + OpenStreetMap. Каталог мест: Overpass + Photon.
- Генерация маршрута: сначала эталонные маршруты, иначе кластеризация каталога OSM, обогащённого базой знаний (kb_places/kb_facts). Kimi (Moonshot) вызывается только как запасной путь и только если есть `MOONSHOT_API_KEY`.

## Экраны генерации

Главная и готовый маршрут — разные экраны, не дописка в конец страницы.

1. «Собрать маршрут» сразу прячет форму и открывает полноэкранный лоадер («Собираем маршрут по картам и гидам...», при непустой базе знаний — «Анализируем N маршрутов и отзывов путешественников...» с реальным N из `/api/kb-stats`).
2. Когда план готов, показывается только экран результата (`#result`), у формы `display: none`.
3. «Назад» (`resetToStart`) возвращает на чистую главную и восстанавливает параметры поиска.

Классы на `body`: `loading-mode`, `result-mode`. Стили изоляции — в конце `public/travelbase.css`.

Готовый маршрут из карусели открывает нижнюю шторку «Осуществить поиск?» и после «Да» идёт тем же путём (лоадер → отдельный экран), а не дописывает HTML вниз.

## Что уже работает в этой сборке

- Четыре вкладки: Главная, Поездки, Тарифы, Кабинет.
- Переключатель «мир / Россия», популярные карточки подставляют город в поиск.
- CTA «Собрать маршрут» под полями поиска.
- Квиз подбора направления (6 вопросов → сравнение направлений, таблица на десктопе / карточки на мобильном) — `POST /api/match-destinations`, скоринг через Kimi или эвристика без ключа.
- Пустые «Мои путешествия»: текст «Пока здесь пусто. Время спланировать новое приключение!» и карусель рекомендаций.
- Сердечки на карточках, на экране плана и на городах. Избранное в кабинете. Таблица `favorites`, для гостя — `localStorage`.
- Бесплатно 2 дня маршрута на направление, остальное за подпиской. Повтор того же города берётся из `destination_cache`, а не генерируется заново.
- Демонстрационные маршруты: Рим (5 дней) и Алтай (4 дня, Чемал, Гейзерное озеро, слияние Чуи и Катуни). Обрезаются до 2 бесплатных дней, если нет подписки.
- Оплата: экран checkout и запись покупки. Это не боевой эквайринг Продамус / Робокасса / PaySelection.
- База знаний: краулер + экстрактор (раздел «Контур базы знаний»), онлайн-обогащение каталога описаниями/ценами, районами и советами из `kb_facts`, метрика `kbHits` в ответе generate.
- Кэш внешних геосервисов (Nominatim/Overpass/Photon) в таблице `geo_cache`, TTL 7 дней — повторная генерация по городу без сети.
- Rate-limiting дорогих эндпоинтов (`generate`, `knowledge-suggest`, `match-destinations`) — in-memory sliding window, HTTP 429 + Retry-After.
- ИИ — Kimi (Moonshot AI): запасной путь генерации, knowledge-suggest с приоритетом направлений из базы знаний, скоринг в квизе. Без ключа всё работает на search-контуре/эвристике.
- Тесты продуктовой логики (`npm test`): сборка маршрута из каталога, схемы плана и экстракции, санитайзинг/безопасность, rate-limit, скоринг квиза.

## Переменные окружения

Файл `.env` в репозиторий не класть.

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | Боевой Postgres. Пусто — локальный PGLite. |
| `MOONSHOT_API_KEY` | Kimi (Moonshot AI). Без него: генерация работает на search-контуре (каталог OSM + база знаний), ИИ-запасной путь выключен. |
| `MOONSHOT_BASE_URL` | Необязательно, дефолт `https://api.moonshot.ai/v1`. |
| `MOONSHOT_MODEL` | Необязательно, дефолт `kimi-k2-0905-preview`. |
| `TELEGRAM_BOT_TOKEN` | Проверка подписи `initData`. Без токена в проде Telegram-идентичность отклоняется. |

## Контур базы знаний

Офлайн-пайплайн (не в request-цикле сервера):

1. `node scripts/crawl-sources.mjs --all` — краулер 10 русскоязычных источников (адаптеры в `scripts/crawlers/`), сырой корпус в `raw_documents`. Локально пишет в `data/kb.db` (PGLite-файл), с `DATABASE_URL` — в общий Postgres.
2. `node scripts/extract-knowledge.mjs` — Kimi извлекает места/факты/маршруты в `kb_places` / `kb_facts` / `kb_routes`. Требует `MOONSHOT_API_KEY`.

Онлайн: `catalogForCity` мёржит `kb_places` в каталог (описания, цены, priority), районы дней — reverse-geocode центроида кластера, советы — из `kb_facts`, ответ generate несёт `kbHits`. Локальное превью (in-memory PGLite) базу знаний из `data/kb.db` не видит — нужен общий `DATABASE_URL`.

## Что сознательно не сделано

Туры по интересам, голосовой ввод, CRM, боевой эквайринг. Это следующие этапы, не баги этой сборки.

## Чего нет в архиве

`node_modules`, кэш сборки (`.vercel`), скриншоты QA, предыдущий zip `travelbase-burgundy`. После `npm install` проект собирается из этого дерева.
